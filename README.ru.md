# ai-agent-rules

Постоянные правила одного человека для ИИ-агентов, одним файлом, общие для всех
инструментов и всех репозиториев машины.

Это ровно то, что иначе повторяешь в чате каждый день и копируешь из проекта
в проект, пока копии не разойдутся: коммит только по просьбе, наружу ничего без
одобрения, вопросы задаются на этапе плана, файл правил не журнал работ.
Всё это в [`AGENTS.md`](AGENTS.md).

## Как устроено

Claude Code читает `~/.claude/CLAUDE.md`, Codex читает `~/.codex/AGENTS.md`. Оба
файла — симлинки в клон этого репозитория, поэтому правится один файл, а видят его
оба инструмента. Правка действует с момента сохранения, а в историю попадает
коммитом и пушем.

Строгость правила помечена. **[жёстко]** репозиторий переопределить не может.
**[по умолчанию]** молча уступает правилу проекта, благодаря чему файл применим
и в репозиториях, где свои правила уже есть.

Канонический документ — `AGENTS.md`, `AGENTS.ru.md` рядом с ним русская копия.
`CLAUDE.md` — симлинк на `AGENTS.md`, как и предписывают сами правила.

[`templates/plan.ru.md`](templates/plan.ru.md) задаёт форму плана работ, чтобы агент
следовал одной структуре, а не придумывал её заново каждый раз.

## Установка

```bash
git clone git@github.com:svesh87/ai-agent-rules.git
cd ai-agent-rules
./install.sh
```

Скрипт вешает `~/.claude/CLAUDE.md` и `~/.codex/AGENTS.md` на `AGENTS.md` из клона
и дописывает `tmp/` и `*.local.md` в общемашинный git-игнор. Больше он не трогает
ничего, root ему не нужен, всё заменяемое сохраняется в резервную копию, повторный
запуск безопасен.

Если удобнее руками:

```bash
ln -sfn "$PWD/AGENTS.md" ~/.claude/CLAUDE.md
ln -sfn "$PWD/AGENTS.md" ~/.codex/AGENTS.md
printf 'tmp/\n*.local.md\n' >> ~/.config/git/ignore
```

Где лежит клон, дело ваше: путь зашит в симлинки, поэтому после переезда клона
`install.sh` запускается заново.

## Обновление

```bash
git pull
```

Больше ничего. Симлинки смотрят в рабочее дерево, так что `pull` и есть обновление.

Изменение правила — это правка, коммит и пуш в таком порядке, и правка действует
с момента сохранения файла. Сами правила требуют перед этим ещё одного шага:
сверить новый пункт со всем файлом, а не с соседями по разделу, потому что ловить
имеет смысл противоречия между далёкими друг от друга местами.

## Как приспособить под себя

Форкнуть и начать с того, что очевидно личное:

- язык чата, первая строка раздела **Язык и тон**;
- скилл `pohuy` и разрешение материться в чате;
- аппаратный ключ, из которого вырос весь раздел **Git**: подпись требует
  физического касания, поэтому коммит не предлагается по своей инициативе
  и не повторяется больше одного раза;
- конкретные имена инструментов в разделе **Наружу ничего не уходит автоматически**,
  то есть MCP-серверы, которые оказались на этой машине.

Остальное не столько личное, сколько пристрастное, и его стоит прочитать до того,
как удалять. Правила про `tmp/`, про аудиты разных моделей и про дубли между этим
файлом и правилами проекта появились потому, что за каждое уже заплачено.
